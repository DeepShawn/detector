# 火眼金睛

**A社临时审核员的赛博养家模拟器**：虚构黑色喜剧 · 叙事解谜 / 卡牌推理。

- 完整策划案：[docs/GDD.md](docs/GDD.md)（GDD v1.1）
- 当前可玩内容：**模式C · 订阅退款拦截战**，工单 **C-1《bagel_lover的退款工单》**（GDD 5.7）

> 本作不采集任何真实系统信息，所有设备档案均为虚构、由玩家手动选择。所有“话术卡”均为抽象叙事卡牌，不映射任何现实操作。现实中订阅退款请遵守平台规则与消费者权益法。

## 运行

```bash
npm start                    # http://localhost:8080
npm test                     # 数据校验 + 退款状态机单元测试
npm install && npm run e2e   # 端到端测试（Playwright：手机 / 平板 / 桌面三种布局）
```

这是一个纯网页原型（无构建步骤），用来先验证模式C的规则和节奏；正式版按 GDD 建议使用 Godot 4 或 Unity。原型里的状态机和数据格式都是引擎无关的 JSON，可以直接迁移。

## 为了能玩，原型补充的规则（GDD 未规定，待策划确认）

全部在 `data/rules.json` / `data/cards.json` / `data/platforms.json` 中，可直接改数值：

- **初始资源**：拦截率 0、投诉 0、监管 0、人性 50、家人安全 80、系统信任 50。
- **回合**：每单最多 3 回合，每张卡每单限用一次。
- **终结卡**：真退款 → 已退款；举报规则 → 规则被举报；假承诺、自动续费暗门 → 暂时平息，并在结算时触发“一个月后”事件（假承诺：投诉 +25；暗门：投诉 +30、监管 +10）。
- **补偿券**：打出后投诉值 ≤ 10 则用户和解。
- **转人工**：本回合状态不推进（“拖延一回合”）。
- **状态推进**：按投诉值只升不降：≥20 用户升级、≥35 平台介入、≥50 社交媒体曝光、≥70 监管投诉；进入监管投诉后每回合监管风险 +10（集体投诉）。
- **情感绑架**：在“用户升级”及之后打出会被截图，监管 +20（C-1 手牌里没有这张）。
- **爆雷**：监管风险达到 100 → 监管爆雷，家人安全 -20。
- **回合用完**：投诉 < 30 → 和解；否则平台介入强制退款（拦截率 -30、监管 +10、系统信任 -10）。
- **系统评分**：拦截率 ≥20 A、≥10 B、≥0 C，否则 D；爆雷固定 F。
- **真相评分**：举报 A、真退款 B、强制退款/爆雷 D、暂时平息/和解 F。
- **开除**：举报后系统信任 ≤ 20 时提示被开除（原型不影响后续）。
- **平台修正**：iOS 拖字诀拦截 +5、条款迷宫 -5；Android 转人工拦截 +10、投诉 +5；Windows 条款迷宫拦截 +10；macOS 假承诺监管 +10；Linux 甩锅风控拦截 -10、投诉 +15。

## 目录

```
docs/GDD.md              完整策划案
data/cards.json          话术卡（效果、副作用、系统红字）
data/platforms.json      五端虚构设备档案与数值修正
data/rules.json          初始资源、状态阶梯、结局与评分规则
data/tickets/C-1.json    工单：用户信息、手牌、用户反应、结局文案、家人评语
js/engine.js             退款状态机（纯函数，引擎无关）
js/main.js               界面
tools/validate-data.mjs  数据校验（引用、结局文案、家人评语是否齐全）
tests/                   单元测试与端到端测试
```

## 新增一张工单

在 `data/tickets/` 新建 `C-x.json`（结构参照 C-1），运行 `npm run validate`。目前界面只加载 C-1，多工单队列与“每个状态影响下一单难度”属于 M1。
